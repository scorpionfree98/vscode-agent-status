### 新发现与修复

#### 🔴 已修复严重问题：繁忙 TUI 终端的阻塞写入

- 位置：`src/terminal-manager.js`
- 复现：向真实 Codex `/dev/pts/100` 以普通 `'w'` 标志打开并写入 OSC，Node 进程持续阻塞，无结果返回。
- 根因：全屏 TUI 繁忙时，PTY 的普通打开/写入可受终端背压影响；该 I/O 位于扩展刷新链路，会导致状态栏和侧边栏停止刷新。
- 采用方案：以 `O_WRONLY | O_NONBLOCK | O_NOCTTY` 打开经白名单验证的 TTY，将标题同步定义为最佳尝试；当输出背压时立即失败并保持刷新链路可用。
- 其他方案未采用：不使用超时后放弃普通阻塞 I/O，因为底层文件操作在超时 Promise 返回后仍可持续占用资源；不回退到激活终端的 VS Code 改名命令，因为会改变用户焦点。
