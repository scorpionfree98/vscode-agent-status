## 技术方案概述

在保留现有 Hook JSON 状态存储的基础上，新增“终端运行时层”与“会话中心表现层”。每次刷新先枚举 VS Code 集成终端并建立 TTY 映射，再将会话派生为“可切换”或“终端已关闭”。状态栏只展示可操作会话，侧边栏保留完整历史。终端命名由扩展按精确 TTY 直接写入 OSC，不激活后台终端；终端已关闭时通过白名单命令一键恢复指定 session。

## 技术选型

| 类别 | 选择 | 理由 |
|------|------|------|
| 语言 | Node.js CommonJS + Python 3 | 沿用现有扩展和 Hook 实现，不新增运行时依赖 |
| UI | VS Code TreeDataProvider | 原生侧边栏 API，支持分组、图标、命令和上下文菜单 |
| 状态存储 | `~/.agent-status/*.json` + `.read` | 保持 Hook 原子写入和已读回执隔离，JSON 同时作为历史索引 |
| 终端绑定 | VS Code Terminal PID → `/proc/<pid>/fd/*` → TTY | 已在当前 Linux Remote 环境验证，可精确匹配 Hook 记录的 TTY |
| 终端改名 | 扩展直接向已验证 TTY 写 OSC 0 | VS Code 无任意后台 Terminal 改名 API；该方式不需切换焦点 |
| 会话恢复 | `createTerminal` + 白名单 CLI 命令 | 可显式设置 cwd，且能校验 session ID 防止命令注入 |

## 架构设计

```text
Codex / Claude Hooks
        |
        v
~/.agent-status/*.json  -----> Session Repository
                                  |
VS Code terminals -> TTY map ---> Lifecycle Reconciler
                                  |
                 +----------------+----------------+
                 |                |                |
             Status Bar      Sessions Tree    Terminal Manager
                                                  |
                                      switch / OSC rename / resume
```

- 数据层：读取 Hook 状态与已读回执，不删除 Agent 原始 transcript。
- 业务层：校验工作区/窗口归属，建立 TTY 映射，计算 `terminalAlive` 和侧边栏分组，处理防重恢复。
- 表现层：状态栏、TreeView、QuickPick 共用同一份派生会话数据。

## 模块划分

| 模块 | 职责 | 依赖 |
|------|------|------|
| `src/state.js` | 纯函数：状态标签、标题规则、分组、安全 session ID、恢复命令 | Node `path` |
| `src/terminal-manager.js` | 终端 TTY 解析、存活映射、OSC 改名、终端切换与创建 | VS Code API, `fs` |
| `src/session-tree.js` | 侧边栏分组与 TreeItem 构建 | VS Code API, `state.js` |
| `src/extension.js` | 状态读取、生命周期编排、命令注册、已读管理 | 上述模块 |
| `scripts/agent-status-hook.py` | 接收 Hook、原子写状态、必要通知 | 不再负责 VS Code 终端命名 |

## 接口设计

### 终端存活映射

- 输入：`vscode.window.terminals`
- 输出：`Map<tty, Terminal>`
- 规则：仅接受 `/dev/pts/<number>` 或 `/dev/tty*`；解析失败的终端不参与自动绑定。

### 会话派生模型

```js
{
  ...hookState,
  terminalAlive: boolean,
  effectiveStatus: 'running' | 'waiting_input' | 'waiting_permission' |
                   'completed' | 'interrupted' | 'stale' |
                   'session_ended' | 'disconnected'
}
```

`effectiveStatus` 只用于 UI，不回写 Hook JSON，防止终端暂时消失时覆盖真实 Agent 状态。

### 树视图命令

- `agentStatus.openSession(state)`：存活终端精确切换；Codex IDE 会话打开对应侧栏。
- `agentStatus.resumeSession(state)`：先检查存活终端与恢复中锁，再新建终端执行指定 session 恢复。
- `agentStatus.markSessionRead(state)`：只为指定状态转移写入已读回执。
- `agentStatus.refreshSessions()`：立即重新读取状态并校验终端。

### 恢复命令

- Codex：`codex resume <session-id>`
- Claude Code：`claude --resume <session-id>`
- cwd 通过 `createTerminal({ cwd })` 传入，不拼接 `cd`。
- session ID 必须通过安全字符白名单，不执行状态文件中的任意命令。

## 数据模型

现有 version 1 Hook 状态保持兼容，本轮不迁移存储格式。扩展内存新增：

- `terminalBindings: Map<string, Terminal>`：本 VS Code 窗口存活 TTY 映射。
- `resumeTerminals: Map<string, Terminal>`：恢复指令与新终端映射，覆盖 Hook 建立新 TTY 绑定前的竞态窗口。
- `lastTerminalTitles: Map<string, string>`：按 TTY 缓存已写标题，避免周期性重复写入。

## 关键设计决策

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 关闭状态是否回写 | 不回写，作为 UI 派生状态 | Hook 状态和终端生命周期是不同事实源 |
| 恢复方式 | 用户点击后一键恢复 | 避免 Reload 时意外启动多个 Agent 和产生费用 |
| 终端命名顺序 | `Agent｜任务｜状态` | 多终端时任务辨识比状态更重要 |
| 已读对标题的影响 | 不改变真实状态文案 | “已读”是通知属性，不是 Agent 生命周期 |
| 无法精确匹配时 | 不改名、不切换 | 优先防止操作错误终端 |

## 实现计划

1. 抽取终端管理模块，建立存活映射与派生状态，收紧状态栏候选集。
2. 将终端命名改为按 TTY 的无焦点 OSC 更新，删除 Hook 端 OSC 竞争通路。
3. 新增 Agent Sessions TreeView，实现需要处理、运行中、终端已关闭、最近记录四组及项操作。
4. 实现 Codex/Claude 一键恢复、cwd/session 校验与防重锁。
5. 补齐纯函数、VS Code mock、Hook 回归和真实 TTY 验证；运行全量测试。
6. 升级版本，打包 VSIX，安装到当前 VS Code Server，不主动 Reload 以免中断当前 Codex。
7. 检查差异和仓库状态，提交并推送 main。

## 风险与降级

- OSC 写入受 Linux TTY 权限影响；失败时仅记录警告，不回退到会抢焦点的更名方式。
- Codex 的 session → TUI PID 映射依赖本地内部日志库；失效时保留历史和恢复能力，但不猜测存活终端。
- VS Code Reload 会中断当前扩展宿主和 Codex 连接；安装后由用户在合适时机 Reload。
