## 需求概述

将插件从“右下角单条状态提示”升级为 Agent 会话中心：状态栏负责提醒最重要的当前任务，侧边栏完整保存 Codex 与 Claude Code 会话记录；用户可以定位仍存活的终端，也可以为已经关闭的终端一键新建终端并恢复原会话。

## 核心交互原则

- 关闭终端不等于删除历史：活动列表移除，历史列表保留。
- 只隐藏终端面板不等于关闭终端：进程仍存活时应继续显示为活动。
- 恢复必须由用户点击触发，默认不在 VS Code 启动时自动拉起 Agent，避免重复运行和意外消耗。
- 同一个 session 同一时间最多绑定一个活动终端；恢复前必须检查是否已有存活终端。
- 状态栏只展示当前窗口可操作的任务；侧边栏承担完整历史、搜索和管理。

## 功能需求

### P0 - 必须实现

- [ ] 终端生命周期：识别“活动、终端已关闭、等待输入、已完成、已中断、状态未知”，终端进程消失后不再显示为可切换活动终端。
- [ ] 侧边栏会话中心：按“需要处理、运行中、终端已关闭、最近完成”分组展示 Codex 与 Claude Code 会话。
- [ ] 精确切换：会话仍绑定存活终端时，点击后聚焦对应 VS Code 集成终端。
- [ ] 一键恢复：终端已关闭时，点击“恢复”新建集成终端，在原工作目录恢复指定 session。
- [ ] 防重复恢复：恢复前检查 session 是否已经在其他终端运行；存在时只切换，不再次启动。
- [ ] 状态栏收敛：已关闭或不可操作的终端会话不继续占用右下角主状态，但历史仍可从侧边栏找到。
- [ ] 真实存活校验：TTY、PID 或 VS Code 窗口失效时及时更新，不把历史绑定当作当前活动绑定。

### P1 - 重要功能

- [ ] 搜索与过滤：支持按任务名、项目目录、session ID、Agent 类型和状态过滤。
- [ ] 会话详情：展示任务简称、工作目录、Agent、状态、更新时间、终端名称、session ID 与最后状态说明。
- [ ] 收藏与重命名：允许为重要会话添加星标和自定义显示名，不受后续 prompt 覆盖。
- [ ] 未读中心：侧边栏分组显示等待授权、等待输入和已完成未读任务，并支持单条或批量已读。
- [ ] 历史保留策略：可配置保留天数和最大记录数；清理只删除插件索引，不删除 Codex/Claude 原始会话。
- [ ] 恢复失败诊断：命令不可用、目录不存在、session 不存在或终端启动失败时给出明确原因和可复制命令。
- [ ] 当前窗口隔离：默认只展示当前 VS Code 窗口/工作区相关活动会话，可切换到“全部记录”。

### P2 - 可选功能

- [ ] 项目视图：按仓库或工作目录聚合会话，展示每个项目的运行中、待处理和最近完成数量。
- [ ] 会话时间线：展示开始、工具执行、等待输入、完成、中断、恢复等关键节点。
- [ ] 批量恢复工作台：一键恢复上次关闭窗口前的多个终端布局，但必须逐项防重复。
- [ ] 快捷操作：复制恢复命令、在新窗口打开目录、归档、删除插件记录、打开 transcript 文件。
- [ ] 通知策略：按项目设置免打扰、仅等待输入通知、完成通知合并和频率限制。
- [ ] 运行统计：按项目统计会话次数、运行时长、完成/中断比例，仅基于本地元数据。
- [ ] 会话交接：生成简短摘要，方便恢复后快速了解上次停在哪里。

## 非功能需求

- 性能：常规刷新不扫描完整 transcript；侧边栏首次打开目标响应时间小于 300 ms，后台存活检测避免高频遍历全部 `/proc`。
- 一致性：Hook 状态、已读回执、终端存活状态相互独立，任何旧写入不得覆盖新状态。
- 安全：恢复命令使用参数化或严格 shell 转义；不执行来自状态文件的任意命令；状态与索引文件权限保持为当前用户私有。
- 可靠性：VS Code Reload、SSH 断连和 Hook 暂时缺失后，侧边栏仍能恢复已有索引并重新校验终端。
- 兼容性：Codex 与 Claude Code 共用界面和生命周期模型，但使用各自官方/现有的 session 恢复能力。

## 边界与约束

- 不自动恢复正在执行的工具调用；恢复的是会话上下文，不承诺重放被中断的命令。
- 默认不在 VS Code 启动时无确认拉起多个 Agent。
- 不删除或修改 Codex/Claude 的原始历史与 transcript。
- Codex transcript 格式不是稳定 Hook 接口，核心记录应来自插件自己的状态目录；transcript 只作为增强信息。
- 旧记录若从未经过新版 Hook，可能缺少完整任务名、终端或窗口绑定，应显示为历史而不是猜测绑定。

## 验收标准

### 终端关闭检测

- Given 一个 session 已绑定集成终端，When 用户真正终止该终端进程，Then 该 session 在短暂宽限期后变为“终端已关闭”，不再执行切换动作，但仍保留在历史列表。
- Given 用户只是隐藏终端面板，When Agent 进程和 TTY 仍存活，Then session 继续显示为活动，点击可以重新聚焦该终端。

### 一键恢复

- Given 一个可恢复的 Codex 历史 session，When 用户点击“恢复”，Then 插件在保存的 cwd 新建终端并恢复指定 session，成功后更新为活动终端。
- Given session 已在某个终端运行，When 用户再次点击“恢复”，Then 插件切换到已有终端，不创建第二个实例。
- Given cwd 或 session 不可用，When 用户点击“恢复”，Then 插件不运行错误命令，并展示可操作的失败原因。

### 侧边栏

- Given 同时存在运行中、等待输入、已关闭和已完成记录，When 打开 Agent Sessions 侧边栏，Then 会话按状态分组且计数准确。
- Given 用户输入任务关键词或目录，When 搜索，Then 仅显示匹配记录且不改变其已读状态。

### 状态栏

- Given 当前主 session 的终端已关闭，When存活检测完成，Then 状态栏自动选择当前窗口下一个可操作任务；若没有则隐藏。

## 待确认项

- “自动恢复”建议定义为一键恢复；是否还需要可选的“打开工作区时自动恢复上次终端”，需单独开启并增加确认与数量上限。
- 侧边栏默认范围建议为“当前工作区”，并提供“全部记录”切换。
- 已完成历史建议默认保留 30 天；收藏记录不自动清理。

## 需求概述

对插件管理的 Codex 与 Claude Code 集成终端实行稳定、可识别的自动命名，使终端标签始终反映该终端实际绑定的 Agent、任务摘要与当前状态，不因用户切换 session、后台任务更新或已读操作而错改其他终端的名称。

## 功能需求

### P0 - 必须实现

- [ ] 统一命名格式：终端名称默认为 `Agent｜任务摘要｜状态`，例如 `Codex｜修复终端切换｜运行中`。
- [ ] 精确归属：只能依据存活终端的 TTY/进程绑定更新名称，不得依据当前选中 session 或最新状态猜测目标终端。
- [ ] 状态同步：当 session 在运行中、等待输入、等待授权、已完成、已中断等状态之间变化时，对应终端标签自动更新，无需先点击或切换该终端。
- [ ] 任务同步：同一 session 提交新任务后更新任务摘要；其他 session 的 prompt 不得影响该终端。
- [ ] 终端列表事件：终端新建、恢复或 VS Code Reload 后，插件完成存活校验即补齐正确名称；终端关闭后停止更名。
- [ ] 单一更名主体：在 VS Code 中由插件统一管理终端标签，Hook 不再尝试从后台进程直接写 OSC 标题，避免两条通路竞争。
- [ ] 可读长度：任务摘要需去掉换行和冗余空白，超长时截断并保留省略号，整体名称不得无限增长。

### P1 - 重要功能

- [ ] 用户命名优先：用户在侧边栏为 session 设置自定义名称后，终端使用自定义名，后续 prompt 只更新原始任务摘要，不覆盖用户名称。
- [ ] 可配置模板：允许用户在有限安全占位符中调整 Agent、任务和状态的顺序，并可关闭自动更名。
- [ ] 名称冲突辨识：多个终端的显示名相同时，增加简短的项目或 session 辨识信息，但不显示完整 UUID。

### P2 - 可选功能

- [ ] 用户手动更名保护：可选检测用户在 VS Code 中手动更名，并询问是否将其保存为 session 的自定义名。

## 非功能需求

- 一致性：一次刷新必须先建立“存活终端 TTY → session”映射，再执行更名；不得暂时激活非目标终端来完成更名。
- 可用性：更名不得抢占终端焦点、展开已隐藏的终端面板或改变用户当前选中项。
- 性能：仅对标题实际发生变化的终端执行更名，避免每 3 秒无条件重复写入。
- 兼容性：Codex 和 Claude Code 使用相同命名规则；某个 Agent 缺失精确终端绑定时，宁可保留原名也不得猜测更名。

## 边界与约束

- 只管理已被插件确认绑定的 Agent 集成终端，不修改普通 shell、构建、调试等终端。
- 已读/未读属于通知属性，不建议作为主终端状态；已读后仍保留“已完成”或“等待输入”等实际运行状态。
- 终端关闭后会话进入侧边栏历史/可恢复分组，不再存在可更名的终端实体。

## 验收标准

### 精确命名

- Given 两个 Agent session 在不同终端同时运行，When 其中一个 session 变为等待输入，Then 只有它绑定的终端变为 `Agent｜任务｜等待输入`，另一终端名称不变。
- Given 用户当前正在查看终端 A，When 后台终端 B 的状态变化，Then B 的标题自动更新，A 仍保持焦点且名称正确。
- Given 当前固定的侧边栏 session 与活动终端不同，When 执行状态刷新或已读操作，Then 不会把固定 session 的名称写到活动终端。

### 状态与恢复

- Given 绑定终端处于运行中，When Hook 报告已完成，Then 终端名在下一次刷新内变为 `Agent｜任务｜已完成`，不因通知已读而变为含义模糊的“已读”终端状态。
- Given 终端已真正关闭，When 旧状态文件再次刷新，Then 插件不会将该名称写到其他终端，恢复 session 后新终端获得正确名称。
